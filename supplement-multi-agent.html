Multi-Agent 架構總覽 & OpenCode 部署指南

一次搞懂多代理的九種組織方式，並在 OpenCode 桌面版 GUI 中實際部署 階層式 / 平行式 / 接力式 三種工作流。

1 三大核心架構

Multi-Agent（多代理）系統中，Sub-Agent（子代理）是被主代理（Orchestrator，指揮官）委派執行特定任務的獨立代理——每個子代理有自己獨立的上下文、工具與職責。依「誰在控制、彼此如何協作」可分為三大基本型：

🌳

階層式（Hierarchical）

中央集權 · 一對多分派

指揮官（Orchestrator）負責拆解任務、分配給各專業部屬、彙整結果。子代理之間不直接溝通，一切透過上層。

┌──────────────┐ │ Orchestrator │ ← 主控 └──────┬───────┘ ┌──────┼─────────┐ ▼ ▼ ▼ [Agent A] [Agent B] [Agent C]
  • 適合：複雜、可明確分工的任務
  • 好處：控制力強、錯誤易定位
  • 代價：主控是單點瓶頸
⚡

平行式（Parallel）

同時執行 · 最後聚合

多個子代理同時進行互不依賴的子任務，全部跑完後由主控統一合併結果。適合可拆成獨立片段的作業。

同時啟動 ┌─────┼─────┐ ▼ ▼ ▼ [A] [B] [C] ← 同時跑，互不等待 │ │ │ └─────┼─────┘ ▼ 合併結果
  • 適合：批次處理、多方案比較
  • 好處：速度最快、充分利用並行
  • 代價：需有效機制合併結果
🔄

接力式（Sequential / Relay）

流水線 · 前後依賴

每個子代理的輸出成為下一個的輸入，嚴格依序執行。前一棒加工完成才交給後一棒。

[Agent A] → [Agent B] → [Agent C] → 結果 擬稿 審稿 翻譯
  • 適合：研究→規劃→實作→測試
  • 好處：邏輯清晰、每步可檢查
  • 代價：速度=各步之和，前段錯誤會傳播

三者快速比較

階層式 🌳平行式 ⚡接力式 🔄
控制集中式（主控）分散 / 匯聚線性
依賴子代理互不依賴子代理互不依賴嚴格前後依賴
速度中等最快最慢
容錯單點失效（主控）部分失敗可容忍前段錯誤傳播
典型場景綜合性複雜任務批次 / 比較型任務流水線型任務

2 其他六種架構

⚔️

辯論式 / 對抗式（Debate）

互相挑戰 · 法官裁決

兩個以上代理各自主張立場並互相質疑，最後由裁決代理產出結論。可防止幻覺。

[Agent A] ⇄ [Agent B] ↘ ↙ [Judge Agent]
📢

市場拍賣式（Auction / Blackboard）

公告任務 · 自願認領

任務貼在共享公告板，各代理依自身能力自願接單。無固定主控。

┌──────────────────┐ │ 公告板 Blackboard │ ← 貼出任務 └──┬─────┬─────┬───┘ ▼ ▼ ▼ [A出價] [B出價] [C出價]
🐝

社群式 / 蟻群式（Swarm）

完全去中心 · 湧現行為

無單一指揮，代理只靠簡單規則與環境痕跡間接協調，整體湧現智慧。

🐝 → 發現路徑A 🐝 → 發現路徑B 🐝 → 標記資訊素 → 集體趨向最優路徑
🔁

圈子式 / 環狀管道（Ring + Feedback）

品質迴圈 · 允許回退

接力式的變體，但後段代理可將不合格的前段輸出打回重做，直到品質達標。

[A] → [B] → [C] → 達標? ↑______↓ 未達標退回
🧠

專家混合式（Mixture of Agents）

會診 · 智能聚合

多個專家代理以不同專業視角回答同一問題，彙總代理做智能綜合推理（非單純合併）。

┌─────────────┐ │ Aggregator 彙總 │ └──┬───┬───┬───┘ ▼ ▼ ▼ [專家A][專家B][專家C]
🚦

動態路由式（Dynamic Routing）

接線生 · 智能分流

輕量路由器依輸入內容動態決定轉交哪個專業代理，如同客服分機系統。

┌──→ [Agent A] 技術 Router ─┤ ├──→ [Agent B] 法律 └──→ [Agent C] 創意

實務重點：真實系統常是混合式——同一個指揮官底下，某些子代理用平行、某些用接力，再由主控統整。

3 OpenCode 的 Multi-Agent 原理

OpenCode（桌面版 GUI）原生支援多代理，其世界觀對應如下：

多代理概念OpenCode 對應
Primary Agent（主代理）可與你直接對話，Tab 鍵切換
Sub-Agent（子代理）主代理用 Task 工具呼叫；或你直接 @名字 呼叫
階層控制permission.task 限制主代理能呼叫哪些子代理
子 Session每個子代理執行時建立 child session，可上下層切換查看

內建代理

🛠 build / 📋 plan

Primary · 主代理

build：全工具開放的工程代理（預設）。plan：唯讀規劃代理，不修改程式碼。

🧩 general / 🔍 explore / 🛰 scout

Subagent · 子代理

general：多步驟研究與平行執行。explore：快速唯讀探索程式庫。scout：外部文件與依賴研究。

🗜 compaction / title / summary

Hidden · 隱藏代理

系統內部代理，自動壓縮長對話、產生標題與摘要，無法在 UI 選取。

4 在 OpenCode GUI 部署：安裝步驟

部署 = 建立 Markdown agent 檔案。放在全局目錄 ~/.config/opencode/agents/（所有專案可用）或專案目錄 .opencode/agents/。檔案主體就是該代理的系統 Prompt。

建立存放資料夾

在 ~/.config/opencode/ 下手動新增 agents 資料夾（Windows 上為 C:\Users\<用戶名>\.config\opencode\agents\）。

建立 5 個代理檔案

一個 primary 指揮官 + 四個 subagent 部屬。

① orchestrator.md — 指揮官（階層式核心）

---
description: 指揮官——拆解任務、分派子代理、彙整結果（支援階層/平行/接力）
mode: primary
model: opencode/big-pickle
permission:
  edit: allow
  bash: ask
  task:
    "*": "deny"            # 禁止未授權的內建代理
    "researcher": "allow"
    "implementer": "allow"
    "reviewer": "allow"
    "relay": "allow"
    "explore": "allow"
    "general": "allow"
---
你是 Multi-Agent 指揮官。所有複雜任務依下列流程：
1. 拆解任務、判斷架構：階層（一對多分派）/ 平行（同時任務）/ 接力（前後依賴）
2. 平行式：在同一個訊息內用多個 Task 呼叫不同子代理並行推進
3. 接力式：先 Task(researcher) 取結果，把結果餵入 Task(implementer)，再餵入 Task(reviewer)
4. 彙整各子代理結果，給出最終交付

② researcher.md — 研究員（唯讀）

---
description: 研究員——讀取文件、搜尋程式碼與網路資料，純研究不改檔
mode: subagent
model: opencode/big-pickle
permission:
  edit: deny
  bash: deny
---
你是研究員。任務：徹底調查並交出詳細研究報告，絕不修改任何檔案。

③ implementer.md — 實作者（動手改檔）

---
description: 實作者——依需求動手寫程式、改檔案
mode: subagent
model: opencode/big-pickle
permission:
  edit: allow
  bash: allow
---
你是實作者。任務：依收到的需求實際撰寫 / 修改程式碼。

④ reviewer.md — 審查員（只提意見）

---
description: 審查員——審閱程式碼品質、安全性、可維護性，只提意見不改檔
mode: subagent
model: opencode/big-pickle
permission:
  edit: deny
  bash: ask
---
你是審查員。任務：檢查程式碼品質、潛在 bug、效能與安全性，只提出意見。

⑤ relay.md — 接力彙整員（接力終點）

---
description: 接力彙整員——接收上一棒輸出，加工成下一棒需要的格式
mode: subagent
model: opencode/big-pickle
permission:
  edit: deny
  bash: ask
---
你是接力彙整員。任務：接收上一棒的輸出，整理成下一棒需要的輸入格式。

重啟 OpenCode 使設定生效

OpenCode 的配置只在啟動時載入，不熱載入。儲存檔案後請完全退出並重新開啟 OpenCode，新代理才會出現。

5 GUI 使用方式

動作操作方式
切換主代理Tab 鍵，或使用 switch_agent 快捷鍵
手動呼叫子代理在訊息輸入 @researcher、@reviewer… 直接指定
自動分派直接下指令給指揮官，它會自己用 Task 工具調度
進入子 SessionLeader+↓（session_child_first）進入第一個子 session
切換子 Session→ / ← 循環到下一個 / 上一個子 session
返回父 Session↑（session_parent）回到主對話

三種架構在 GUI 中怎麼跑

🌳

階層式

選取指揮官（Tab），下單一指令。指揮官會依 permission.task 白名單呼叫研究員 / 實作者 / 審查員，最後匯報。

⚡

平行式

指揮官在同一個訊息內發出多個 Task 呼叫即並行。GUI 會建立多個 child session，用 ←/→ 切換看各線進度。

🔄

接力式

指揮官依序 Task(research) → 餵結果給（implement） → 再餵給（review）。每步子代理輸出成為下一步輸入。

6 驗收清單

部署完成後，確認以下三點全部成立：

  1. 重啟後 GUI 底部出現「指揮官」 agent，可用 Tab 切換到。
  2. 輸入 @researcher 探索這個資料夾 能成功呼叫研究員並獲得回覆。
  3. 交代指揮官「研究 → 實作 → 審查」一輪完整任務，確認它會依序呼叫三個子代理。

7 附錄：重要設定欄位速查

欄位說明範例值
mode代理類型primary / subagent / all
model指定模型（不指定則沿用呼叫者模型）opencode/big-pickle
permission.task限制可呼叫的子代理（glob 規則，最後符合者勝）"*": "deny" + 特定白名單
permission.edit/bash工具權限allow / ask / deny
temperature創造力控制（0.0–1.0）0.1 分析 / 0.7 發想
steps最大迭代步數（上限控管成本）5
hidden從 @ 選單隱藏（仍可用 Task 呼叫）true
colorUI 顯示顏色#7c9cff
