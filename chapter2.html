05 短期記憶 vs 長期記憶

⚡ 短期記憶

  • 你當前正在跟 AI 對話的內容
  • 隨時能用，但關掉視窗就沒了
  • 就像快捷列上的水藥
  • 容量有限（Context Window）
  • 新資料會擠掉舊資料

💾 長期記憶

  • 儲存在外部資料庫的歷史紀錄
  • 就算過了一個月，Agent 依然記得
  • 就像雲端遊戲存檔
  • 容量幾乎無限
  • 可以跨對話調閱
⚡ 短期記憶
~4K tokens
關掉就消失
像打開的瀏覽器分頁
💾 長期記憶
無限容量
永久保存
像 Google Drive 雲端硬碟
💡 實戰例子：
短期記憶：你跟 Agent 聊了 10 分鐘「今天心情不好」，關掉視窗後再開，它完全忘了這件事
長期記憶：你曾告訴 Agent「我叫小明、我對花生過敏」，一個月後再開對話，它依然記得「小明，你上次說對花生過敏，這道菜有花生，要不要換一道？」
🎮 遊戲比喻：戰鬥中即時翻閱《怪物百科全書》

06 RAG（檢索增強生成）

AI 不需要把全世界的所有知識都硬背進大腦。RAG（Retrieval-Augmented Generation）就像是：
📖 RAG 流程圖
🙋 使用者提問
「公司去年營收多少？」
→
🔍 檢索文件庫
去翻《公司年報》
→
📋 找到相關段落
年報第 15 頁
→
🧠 生成回答
「去年營收 5 億」
RAG 的三大優勢：
  • 不胡說八道：有資料庫撐腰，不會「幻覺」編造數字
  • 不用重新訓練：更新文件庫就好，省下幾百萬訓練費
  • 可追溯來源：可以告訴你「這個答案來自年報第 15 頁」
🎮 類比說明：
想像你在考試，有兩種做法：
不使用 RAG：把整本課本背起來（硬訓練模型），考試時靠記憶回答
使用 RAG：考試可以翻書（檢索文件庫），找到正確頁面後回答（又快又準！）
🔧 動手做時間（第三天）
  1. 在 OpenCode 中問：「我叫小明，我喜歡吃義大利麵」，然後問「我喜歡吃什麼？」—— 確認短期記憶有效
  2. 關掉對話視窗，重新開啟，問「我喜歡吃什麼？」—— 觀察短期記憶消失
  3. 在 OpenCode 中上傳一份文件（如學校課表），問「我星期三有什麼課？」—— 體會 RAG 的威力
  4. 寫下：短期記憶和長期記憶在生活中有什麼類似例子？（提示：手機 vs 雲端相簿）

07 Vector DB 與 Embeddings

電腦不懂文字的浪漫，只懂數字。Embeddings 會把文字轉換成多維度的數字向量（空間座標），把含意相近的詞擺在一起。
🐱 貓
座標：(0.8, 0.9, 0.1)
← 很近！→
🐕 狗
座標：(0.7, 0.8, 0.2)
← 很遠 ✕ →
📻 微波爐
座標：(0.1, 0.2, 0.9)
Vector DB（向量資料庫）就是儲存這些座標的超級圖書館，能讓 Agent 在 0.01 秒內用「意思很像」來找到資料！
🎮 類比說明：
想像一張地圖：
「貓」在台北市的座標是 (25.03, 121.56)
「狗」在新北市的座標是 (25.01, 121.47) — 很近！
「微波爐」在美國的座標是 (37.77, -122.41) — 超遠！

Vector DB 就是這張「語義地圖」，讓 Agent 用意思而不是關鍵字來搜尋。

08 Context Engineering（情境工程）

既然視野（Context Window）有限，就不能把雜物都塞給 Agent。Context Engineering 就是極致的「背包整理術」：

❌ 沒有整理背包

塞入：100頁PDF + 舊對話 + 閒聊
+ 不相關新聞 + 完整程式碼
→ Agent 被資訊淹沒，回答變慢
→ 舊記憶被擠掉，「失憶」了！

✅ 整理過的背包

精選：摘要 + 關鍵段落
+ 最近5輪對話 + 相關檔案
→ Agent 思考更快、更精準
→ 重要記憶不會被擠掉！
Context Engineering 的四大技巧：
  • 刪除垃圾：無關的舊對話、過時的資料直接砍掉
  • 精簡摘要：100 頁文件壓縮成 1 頁重點
  • 排優先序：最重要的資訊放在最前面（Agent 最容易看到）
  • 分段處理：大任務切成小塊，每塊只塞必要的上下文
🎮 類比說明：
你在玩 RPG 時，背包空間只有 20 格：
不整理：塞了 20 個低級藥水，遇到 Boss 時沒有空間放神器
整理後：只帶 5 個高級藥水 + 3 把武器 + 2 個捲軸，打 Boss 時從容應對

Context Engineering 就是 Agent 的「背包整理師」！
🔧 動手做時間（第四天）
  1. 在 OpenCode 中，先問「台北有哪些景點？」，再問「巴黎有哪些景點？」，再問「我前面問的第一個城市的景點有哪些？」—— 觀察 Agent 有沒有記得「台北」
  2. 把一份長文件（超過 1000 字）貼給 Agent，問「幫我摘要這份文件的 3 個重點」—— 體會 Context Engineering 的「精簡」
  3. 問 Agent：「如果我有 100 個客人的資料，你會怎麼快速找到我想要的那一個？」—— 引導它提到 Vector DB
  4. 寫下：為什麼「整理背包」比「買更大的背包」更重要？

⚔️ 第二章小挑戰：搭建帶記憶的 Agent
運用記憶系統的四大概念，讓 Agent 記住你是誰！

🎯 挑戰目標

用 OpenCode GUI 搭建一個對話 Agent，能記得你的個人資訊，並在對話中主動引用。
提交對話截圖 + 程式碼（或對話紀錄）+ 300 字說明。

任務一：建立長期記憶

在對話開始時，告訴 Agent 以下資訊：
「我叫小明，我是國中二年級學生，我對花生過敏，我的生日是 3月15日，我最喜歡的科目是數學」

任務二：驗證記憶

問 Agent 以下問題，確認它有記得：
1. 「我叫什麼名字？」
2. 「我有沒有什麼過敏？」
3. 「我最喜歡什麼科目？」
4. 「幫我規劃一個生日行程」（觀察它有沒有用到 3/15 這個日期）

任務三：跨話題測試

先聊 5 個不相關的話題（如：今天天氣、最近電影、歷史故事、數學問題、一首歌），
然後問：「我之前說我對什麼東西過敏？」—— 觀察 Agent 有沒有「金魚腦」失憶。

任務四：撰寫 300 字說明

寫下：
1. 短期記憶和長期記憶在你的實作中如何運作？（2-3 句）
2. 如果用 RAG 架構，你會把「小明的資料」存在哪裡？（2-3 句）
3. Context Engineering 在你的對話中有什麼影響？（2-3 句）
4. 畫一個簡單的流程圖，說明 Agent 如何「記住」你的資訊

📋 評分標準

評分項目 分數 說明
✅ 長期記憶建立 25 分 Agent 能正確記住 5 項個人資訊
✅ 記憶驗證 25 分 Agent 能正確回答所有問題，並主動引用生日
✅ 跨話題測試 25 分 在聊了 5 個話題後，Agent 仍記得過敏資訊
✅ 300 字說明 25 分 能用自己的話解釋 4 個概念，流程圖正確
